# Getting access to systems

**Owner:** IT & workplace  
**Last edited by:** Rosa Murray (IT Manager)

This page covers how to request access to Kilbarra systems — from joining, moving teams, or leaving — and what to do if a request goes wrong.

## Requesting access

1. Open the IT service desk form from the **IT & workplace** page in the helpdesk. The form is labelled "Access request".
2. Choose the request type:
   - **New joiner** — for people starting in a new role.
   - **Leaver** — for people leaving Kilbarra.
   - **Mover** — for internal transfers or role changes.
3. Fill in the fields:
   - **Person** — the full name as it appears in the HR system.
   - **Team and manager** — current team and manager.
   - **Systems needed** — select from the list. If a system is not listed, type its name and the team that owns it. The IT team will confirm with the system owner.
   - **Start date** — the date access should be active from.
   - **Justification** — one or two sentences on why the access is needed. For movers, also say which systems should be removed.
4. Submit the form. The requester gets a ticket number in the helpdesk.

## How long it takes

- **New joiners**: access is usually ready by the first working day, provided the request arrives at least three working days before the start date. If the request is late, IT will do its best, but some systems may take an extra working day or two.
- **Movers**: most changes complete within two working days. Systems owned by other teams (for example, the treasury workstation or the case tool) may take longer.
- **Leavers**: access is revoked on the day the leaver is marked as left in the HR system. If a leaver needs access for a handover, the manager must request a **temporary extension** through the same form and state the end date.

## Joiners, movers and leavers

- **Joiners** — the hiring manager submits the access request. The people team also triggers an onboarding checklist for the manager, which includes a reminder to raise the access request. Do not wait for the checklist — submit the request as soon as the start date is known.
- **Movers** — the new manager submits the request. The form asks for both the new and previous systems. IT will remove access to systems that are not listed in the "Systems needed" field. The previous manager can request a short extension for handover purposes.
- **Leavers** — the manager submits the request on or before the leaver's final working day. The form includes a **Leaver** option that triggers removal from all systems, including the back office, the merchant dashboard, the core ledger, and the secrets manager. If the leaver is a member of a team that runs on-call, the manager should also check the on-call rota and arrange cover.

## Quarterly access review

Each quarter, the IT team sends reminder emails to all managers asking them to review their team's access. The email links to a report in the back office that lists each team member and the systems they can access. Managers should:

1. Open the report and check each person's access against their current role.
2. Mark any access that is no longer needed.
3. Submit a mover request for each change.

Reviews are due by the last working day of the quarter. If a manager does not complete the review, IT will follow up once, then escalate to the manager's own manager.

## If it goes wrong

- **Access not active on the start date** — check the ticket status in the helpdesk. If it is still open, reply on the ticket. If it is closed, reopen it and say the access is missing.
- **Wrong systems granted** — reply on the original ticket and ask for the incorrect access to be removed. Do not use the systems while the ticket is open.
- **Access not revoked for a leaver** — contact IT & workplace directly in #it-help. This is treated as a priority.
- **Request rejected** — the ticket will say which team rejected it and why. If you believe the rejection is wrong, raise it with that team's lead before contacting IT again.

For anything not covered here, ask in #it-help and include the ticket number if you have one.
